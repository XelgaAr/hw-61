# № 61 · Middleware в Express

Справочник пользователей и статей с текстовым HTTP API. Читатель открывает записи, редактор также создаёт, обновляет и удаляет их. Сервер проверяет сессию, права, идентификатор и входные данные до передачи запроса контроллеру.

## Запуск в VS Code

Откройте папку `hw-61` в VS Code. В терминале выполните команды с Node.js 22.9 или новее и npm.

```sh
npm ci
npm test
npm start
```

Откройте [главную страницу](http://127.0.0.1:3000/). Сервер пишет в терминал время, метод, путь и итоговый HTTP-статус каждого запроса. Для автоматического перезапуска после правок используйте `npm run dev`. Остановить процесс можно сочетанием Ctrl+C.

Чтобы пройти сценарии через интерфейс в браузере, выполните в отдельном терминале:

```sh
npm run demo
```

Откройте [интерактивную демонстрацию](http://localhost:4173/demo/). Для запуска этой демонстрации достаточно одной команды после установки зависимостей.

## Сеанс

У приложения две учебные учётные записи. Логин `reader`, пароль `reader-demo` дают доступ на чтение. Логин `editor`, пароль `editor-demo` разрешают также изменять ресурсы. Записи каталога `/users` и учётные записи для входа хранятся отдельно.

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `GET /` | Всем | Список точек входа |
| `POST /session` | Всем | Проверяет поля `username`, `password` и создаёт сессию с новой cookie `hw61.sid` |
| `GET /session` | После входа | Показывает текущую роль |
| `DELETE /session` | После входа | Уничтожает сессию и очищает cookie |

В адресной строке браузера можно сразу проверить `GET /`. Для входа откройте на этой странице консоль разработчика и выполните:

```js
await fetch('/session', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ username: 'reader', password: 'reader-demo' })
}).then(response => response.text())
```

После входа откройте `/users/1` или `/articles` в той же вкладке. Браузер автоматически приложит cookie. Для выхода выполните `await fetch('/session', { method: 'DELETE' })` в консоли.

## Маршруты каталога

| Метод | Пользователи | Статьи | Доступ и результат |
| --- | --- | --- | --- |
| GET | `/users` | `/articles` | Обе роли. Список записей |
| GET | `/users/:userId` | `/articles/:articleId` | Обе роли. Одна запись |
| POST | `/users` | `/articles` | Редактор. Создание, статус 201 и путь к записи в заголовке `Location` |
| PUT | `/users/:userId` | `/articles/:articleId` | Редактор. Полная замена существующей записи |
| PATCH | `/users/:userId` | `/articles/:articleId` | Редактор. Обновление перечисленных полей |
| DELETE | `/users/:userId` | `/articles/:articleId` | Редактор. Удаление с текстовым подтверждением |

Запросы с телом принимают `application/json`. Успешные ответы и сообщения об ошибках используют `text/plain; charset=utf-8`. В каждом списке первоначально две записи с ID 1 и 2. Сервер сам присваивает положительный целый ID каждой следующей записи.

| Ресурс | Пример для POST или PUT | Проверки |
| --- | --- | --- |
| Пользователь | `{"name":"Ирина","email":"irina@example.org","age":24}` | Имя 2–80 символов, корректный email до 254 символов. Необязательный возраст — целое число 0–120 |
| Статья | `{"title":"Роли в приложении","content":"Читатель может открыть каталог."}` | Обязательные непустые заголовок до 160 символов и текст до 10 000 символов |

При PATCH передайте хотя бы одно поле. Клиентские значения `id` и неизвестные поля отклоняются. Статусы ошибок: 400 для некорректных данных или ID, 401 для отсутствующей сессии или неверных данных входа, 403 при недостатке прав, 404 для отсутствующей записи или маршрута, 413 для тела более 64 КиБ и 415 для неподдерживаемого типа содержимого. Неожиданные ошибки обрабатываются централизованно со статусом 500.

## Настройки и устройство

Для переопределения настроек скопируйте `.env.example` в `.env`. Поддерживаются `HOST`, `PORT`, `READER_PASSWORD`, `EDITOR_PASSWORD` и необязательный `SESSION_SECRET`. По умолчанию сервер слушает `127.0.0.1:3000` и генерирует случайный секрет при запуске. В cookie хранится подписанный идентификатор на 30 минут с флагами HttpOnly и SameSite=Lax. Сервер добавляет Secure при HTTPS. Учебное хранилище находится в памяти процесса. При перезапуске записи возвращаются к исходным значениям, а сессии завершаются.

Каталоги `src/models`, `src/views` и `src/controllers` отвечают за хранение записей, их текстовое представление и обработку CRUD. Маршруты находятся в `src/routes`. В `src/middleware` расположены проверка сессии и прав, валидация Joi, журналирование и обработчик ошибок.

## GitHub Pages

Поместите содержимое этой папки в корень отдельного репозитория. Команда `npm run build` обновляет в `docs/` снимки реальных HTTP-ответов. После загрузки файлов выберите **Settings → Pages → Deploy from a branch → main → /docs → Save**. Опубликованная демонстрация показывает сохранённые запросы и ответы. Чтобы выполнить запросы и проверить изменение данных в действующем Express-процессе, используйте `npm run demo` локально.

Документация: [Express](https://expressjs.com/en/guide/using-middleware.html), [express-session](https://expressjs.com/en/resources/middleware/session.html), [Joi](https://joi.dev/api/18.x.x).
